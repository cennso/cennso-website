# seo-gate: cennso-website

## Metadata bands this repository enforces

`scripts/validate-seo.py` reads the built HTML in `.next/server/pages/**/*.html`.
Titles are 50-60 characters (`validate-seo.py:32`); meta descriptions are 150-160
(`validate-seo.py:46`). Both are warnings there (`validate-seo.py:186`,
`validate-seo.py:200`), not errors — `main()` only returns non-zero when
`has_errors` is set (`validate-seo.py:328`), so a title or description outside
the band will not fail the build and has to be caught in review.

## Structured data per page type

`components/SEO.tsx:84-85` emits Organization and BreadcrumbList on EVERY page
automatically (`generateOrganizationSchema()` / `generateBreadcrumbSchema(...)`,
combined into `allSchemas` a few lines below). A page does not add those
itself. Page-specific types are passed through `SEO`'s `structuredData` prop,
generated by `lib/seo/schema/`:

| Page type | Generator | Type | Called from |
| --- | --- | --- | --- |
| any page | `lib/seo/schema/organization.ts` | Organization | `components/SEO.tsx:84` |
| any page | `lib/seo/schema/breadcrumb.ts` | BreadcrumbList | `components/SEO.tsx:85` |
| blog post | `lib/seo/schema/article.ts` | Article | `pages/blog/[blog-post].tsx:80` |
| solutions index | `lib/seo/schema/faq.ts` | FAQPage | `pages/solutions/index.tsx:39` |
| contact | `lib/seo/schema/local-business.ts` | LocalBusiness | `pages/contact.tsx:44` |
| (nested only) | `lib/seo/schema/person.ts` | Person | `article.ts:36` (blog author), `organization.ts:54` (founder) |

Note the last row is not "called by nothing": `generatePersonSchema` is called
from inside `article.ts` and `organization.ts` to fill the `author`/`founder`
field of an *already-emitted* schema. No page passes a Person schema as its
own top-level `structuredData` — there is no person/team/author page. Do not
report Person as dead code; do treat "add a standalone Person page" as a gap,
not a bug.

`scripts/validate-structured-data.py:43` holds the allowed `@type` list and
`:115-199` (`validate_required_properties`) the required properties per type.

## Known pre-existing defect

Every page that renders `components/PageHeader.tsx` emits a SECOND BreadcrumbList,
from `next-seo`'s `BreadcrumbJsonLd` at `PageHeader.tsx:28-36`, on top of the one
`SEO.tsx:85` already emits. Do not report this as new on a diff that did not cause
it; do report it under `unverifiable` when reviewing a page that renders PageHeader.

## The rule that fails a build

`scripts/check-navigable.py:161-170` requires the literal string `<SEO ` in every
file under `pages/`. A page that renders metadata any other way fails with an
ERROR, not a warning. Treat the removal of a `<SEO ` call from a page as critical.

## Commands

`yarn seo` runs `seo:validate`, `seo:schema` and `seo:links`. All three read built
HTML, so they need `yarn build` first. `yarn validate:ogimages` is separate.

## Also immune to markup changes

`validate-seo.py`, `validate-structured-data.py`, `check-internal-links.py` and
`validate-og-images.py` all parse `.next/server/pages/**/*.html` — the build's
rendered output — not `.tsx` source, so it makes no difference to them whether a
heading or image came from a literal tag or a `@cennso/ui` component. This is
the working precedent `docs/accessibility-checkers-and-cennso-ui.md` points to
for fixing the four a11y checkers that are not similarly immune.

## Out of scope for this gate

`content/privacy-policy.md` links to `https://dg-datenschutz.de/dienstleistungen/`,
which is dead. `scripts/check-internal-links.py` explicitly skips external links
(`check-internal-links.py:68`), so this is not caught there — it is caught by the
separate `.github/workflows/link-check.yml` ("Link check") CI job, which runs
`lychee` against all `**/*.md` on any PR touching Markdown. Pre-existing, not this
diff's fault; do not attribute it to a change that happens to touch the same file.
